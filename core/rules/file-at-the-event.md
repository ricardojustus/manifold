# File at the event — hygiene happens during work; the close only verifies

The moment work produces a durable fact, file it to its home THEN — never "at the end":

- **Finished or changed an implementation** → update the owning plan / current-state doc in the same arc.
- **A settled decision, correction, or hard-won lesson** → the memory store / lessons store now.
- **A backlog item is born** → the project's open-items surface (the binding names it — a file, or an issue tracker), tagged with its OWNER. On a FILE surface, **closing MOVES the entry to the closed-items archive file** (never a struck-through tombstone in the live backlog); on a TRACKER, closing is a state change and the tracker keeps the history.
- **A work item's state changed** (started, parked, abandoned, shipped) → **where the surface is a tracker**, move it AT that moment; a tracker frozen at last week's state is worse than none, because the operator reads it at a glance and believes it. (On a file surface this is just the entry edit above — no separate step.)
- **Something needs the operator's eyes** → the operator-review surface, the moment it parks; **resolving it MOVES the entry to that surface's archive** — the live file keeps only OPEN items, never resolved history (same don't-tombstone rule as the backlog).
- **STATE holds current-state + pointers only** — nothing sits in STATE awaiting later routing.

Session-end then verifies ("anything unfiled?") instead of producing — that is what makes the close cheap without making it thoughtless.
