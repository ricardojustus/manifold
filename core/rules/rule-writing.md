# Rule capture format — rules are rules

An always-loaded rule file states: the RULE (imperative), its scope/trigger, its enforcement. Nothing else. **Scope: the no-inline-receipts and state-the-new-rule-clean bullets govern rules, skills, agent files, templates, and any other always-loaded doc** — not rule files alone; the size target and the one-why-clause limit are rule-file-specific.

- **No inline receipts** — no attributions ("X ruled this"), no dates, no incident stories, no why-this-beat-alternatives essays. A receipt is who decided a rule, when, and where that decision is recorded: it lives in a dedicated receipts file or the project's memory store and is POINTED at, never written inline. Diarize the WHY at capture time; the memory store is the receipts store, retrieved on challenge. (A rule may POINT at a receipts file in a closing line; new receipts are diarized, not filed there.)
- **Anonymized worked examples stay allowed** — an illustrative failure or a concrete case that teaches the rule is content, not a receipt, provided it names no decider and carries no date.
- One "why" clause (≤1 sentence) is allowed where it prevents relitigation; a settled-alternatives line ("Settled — inherit: X died on Y") may name what died and why, one line each, undated.
- **Target ≤ ~1.5 KB per rule file.** Bigger usually means several rules, a skill, or reference material — which belongs in an on-demand surface, never the always-loaded set.
- **When a rule changes, state the new rule clean** — no old-wording references, no changelog in the rule body.
- **Cut persuasion, never precision**: every concrete value (paths, names, commands, thresholds, signatures) survives verbatim.
